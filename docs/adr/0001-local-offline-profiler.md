# Run the profiler as a local offline application

The profiler uses a React/Vite UI and a FastAPI service bound to the user's machine, with no external runtime calls or remote data transfer. This keeps potentially sensitive data on the single user's Windows or macOS machine while moving large-file analysis out of the browser. We prefer this over browser-only analysis for its memory and processing limits, and over a cloud backend to avoid remote upload, permanent retention, and multi-user access requirements.

Raw uploads and normalized worksheet copies are temporary inputs and are deleted when computation finishes. The current successful Column Completeness Summary and latest successful job for each analysis mode may retain imported rows in private local SQLite staging databases while the backend is running. These databases support paginated, user-initiated row details for Column Completeness statuses, Completeness Patterns, Formal Terms, and Group Data. A replacement summary or job, a newly accepted dataset import, applying changed Missing Value rules, graceful backend shutdown, or startup cleanup removes the corresponding retained databases. Data Contract jobs return aggregate counts only and delete their SQLite database when the job finishes successfully. Failed requests and failed or cancelled analysis jobs leave no new row-level data behind. No row data is written to permanent storage.

The API provides paged JSON access to the source rows matching a selected Completeness Pattern, including all source columns in source order, and a streamed CSV download of every matching row. This temporary detail and export access supersedes the former summary-only access decision; the existing column-completeness and pattern-summary CSV downloads remain summary-only.
